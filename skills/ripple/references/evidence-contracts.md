# Evidence Contracts

把以下字段作为信息契约，不把模板数量当成工作量。小任务可在一个短段落或一张表中合并；复杂任务再拆开。路径必须真实，未读取的内容只能标为待查或推断。

## Requirement Brief

| 字段 | 要写什么 |
|---|---|
| Goal | 用户要改变的产品行为，而非仅文件名 |
| Rules | 字段含义、默认值、从属／互斥关系、保存行为等相关规则 |
| In scope | 本次明确允许改变的页面／端／行为 |
| Out of scope | 用户排除项及已决定保留的相关入口 |
| Acceptance | 能观察或测试的完成条件；必要的范围外不变条件 |
| Open questions | 会改变方案的未决项；没有则写无 |
| Revision | 能与批准消息对应的版本或清楚的对话定位 |

## Impact Map

| 业务语义 | 入口／端 | 实际文件／符号 | 共享依赖与影响 | 拟处理方式 | 理由与授权状态 |
|---|---|---|---|---|---|
| 当前规则 | 已查入口 | 已读取的位置 | 谁依赖它、可能怎样变化 | 同步／不改／待定 | 已授权／待批准／范围外；依据 |

附一行“搜索覆盖”：查了哪些目录、调用关系和相关参数；哪些端或模块不可访问。不存在证据时不要写“全局均已检查”。

“拟同步”是方案，不是权限。用户限定入口时，可以列出其他入口并标注保持原行为。未观察到的副作用要作为待验证项，而不是默认为不存在。

## Design Provenance

| 决策类别 | 来源位置 | 继承／修改内容 | 状态 | 限制／新增部分 |
|---|---|---|---|---|
| UI | 用户指定组件或目标端现有模式 | 布局、控件、Footer、间距、操作 | 已验证／推断／冲突／不可访问 | 本次允许改变的部分 |
| 业务规则 | 指定成熟实现或已确认需求 | 字段、默认值、校验、状态关系 | 同上 | 新需求与旧实现差异 |
| 数据约束 | 当前 API／schema／数据模型 | 枚举、持久化值、请求与响应 | 同上 | 未解决兼容问题 |

没有 UI 变化时可写 UI 不适用并说明原因；不能为了填满三行而凭空设计。发现冲突要同时保留各来源，不静默覆盖。

## Prototype

交付能让用户判断方案的产物：位置或对话内内容、方案版本、关键行为、相关状态、使用的 Mock／假设、与正式应用隔离方式。

局部间距调整可以是“原值 → 目标值”的准确对比，不要求重新画整页。涉及布局、层级和交互时，提供足以判断的示意或可交互原型。未实际渲染时，不把源文件说成“已视觉验收”。

## Approval Record

```text
方案版本：
用户授权出处：真实消息定位或必要原文
授权类型：批准方案 / 明确直接实现
允许的行为范围：
明确排除：
跳过原型：是 / 否；依据
仍须满足的其他 Gate 或权限：
```

不需要每次新建审批文件。对话里可追溯即可；跨会话或委派时才持久化必要内容，并遵守项目约定。

## Verification Report

| 验收项／不变条件 | 覆盖的入口／端 | 实际命令或操作 | 代码状态与证据 | 结果 | 缺口／下一步 |
|---|---|---|---|---|---|
| 可观察行为 | 对应范围 | 真正执行的检查 | 输出、退出码、断言、截图或日志定位 | PASS／FAIL／NOT_RUN／BLOCKED | 原因及具体影响 |

记录最终 diff 或任务版本、检查时间与必要输出。截图只证明所展示的状态，不证明 Store、请求参数或未展示平台正确。`N/A` 只用于确实不适用的检查并附理由，不能拿来替代失败或受阻。
